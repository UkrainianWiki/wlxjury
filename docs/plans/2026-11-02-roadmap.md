**A4b (R) Emails and wiki accounts stored with surrounding whitespace** (`stack/102-login-spaces`).
From 26.11 a typed or pasted login, email or wiki account loses its surrounding spaces, tabs,
non-breaking and other Unicode spaces (`LoginText.clean`) before it is looked up or stored. A
stored email that still has them is never found by a sign-in, the add row or an import, and its
invitation and password links are refused (`AccountTokenJdbc` compares the stored `users.email`
with the link's address, which is now stored clean). A stored wiki account with them doesn't match
a password sign-in by that name. `ENDS` is the hex of the Unicode spaces at an
end (U+00A0, U+0085, U+2000–U+200B, U+200E, U+200F, U+2028, U+2029, U+202F, U+205F, U+2060,
U+3000, U+FEFF, U+1680); anchored, so a space inside a value isn't listed:
```sql
-- ENDS = (C2A0|C285|E2808[0-9ABEF]|E280A[89F]|E2819F|E281A0|E38080|EFBBBF|E19A80)
SELECT id, email FROM users WHERE LENGTH(email) <> LENGTH(TRIM(email))
  OR email REGEXP '^[[:space:]]|[[:space:]]$'
  OR LENGTH(email) <> CHAR_LENGTH(email)
  OR HEX(email) REGEXP '^(C2A0|C285|E2808[0-9ABEF]|E280A[89F]|E2819F|E281A0|E38080|EFBBBF|E19A80)|(C2A0|C285|E2808[0-9ABEF]|E280A[89F]|E2819F|E281A0|E38080|EFBBBF|E19A80)$';
SELECT id, wiki_account FROM users WHERE deleted_at IS NULL AND wiki_account IS NOT NULL AND (
  LENGTH(wiki_account) <> LENGTH(TRIM(wiki_account))
  OR wiki_account REGEXP '^[[:space:]]|[[:space:]]$'
  OR HEX(wiki_account) REGEXP '^(C2A0|C285|E2808[0-9ABEF]|E280A[89F]|E2819F|E281A0|E38080|EFBBBF|E19A80)|(C2A0|C285|E2808[0-9ABEF]|E280A[89F]|E2819F|E281A0|E38080|EFBBBF|E19A80)$');
  -- none expected. LENGTH, not `email <> TRIM(email)`: under PAD SPACE collation `<>` misses
  -- trailing spaces. `LENGTH <> CHAR_LENGTH` lists every email with a non-ASCII character
  -- (an invisible one inside it, or a real international address): look at each, change none
  -- that is only international
```

## Running agents (how)

The rules are in [workflow practices](../workflow/practices.md); in short:

- Workflow: implementer → orchestrator check → independent reviewer → fixes by the implementer →
  a second review only if the fixes are material → results recorded in the plan (§2).
- **Only the orchestrator pushes and opens PRs** (an agent only when the user asks for it in
  that task), never with force; edits to another agent's PR body go through the orchestrator or
  the user (§6.3).
- **gh** is `/c/Users/ilya/tools/gh/bin/gh.exe` (not on `PATH`; the review tools take it from
  `GH` or `--gh`). Agents use it read-only unless told otherwise.
- **One sbt/test JVM at a time** across all agents: take `mkdir /c/scala/.sbt-jvm.lock` as its
  own command and check it succeeded (wait and retry if it exists; never delete another's lock),
  `rmdir` after, only if yours (§4.2).
- **Every sbt or Docker run** with the prefix
  `env -u COMMONS_USER -u COMMONS_PASSWORD -u SCALAWIKI_LOGIN -u SCALAWIKI_PASSWORD` (§4.3).
- Checks through `python scripts/agent-check.py -- …` from Git Bash (CLAUDE.md). Affected specs
  per batch; the full suite at the release boundary (CI runs it on every PR).
- Commit with `git commit -- <paths>` and `-F <file>`; the attribution line (§5).
- **Restack by merge, never by force:** a stack branch that needs a lower PR's change gets a
  merge commit (or a new commit), never a rebase or force push of a pushed branch (§6.5).
- **Followups mirrors equal the stack tip by tree:** a commit on the top stack PR is mirrored on
  a followups branch (`git commit-tree <tip>^{tree} -p <followups>`) and `git diff --stat` is
  empty (§6.4).
- Never link or copy `node_modules` or `data/cache` between worktrees. `C:/scala/wlxjury` (main
  checkout, user's untracked files) and `C:/scala/wlxjury-infra` (user's uncommitted work, secrets)
  are not modified by agents.
- CodeRabbit: [`scripts/review/`](../../scripts/review/README.md), one PR at a time.
