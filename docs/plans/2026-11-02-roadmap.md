- **B4, passwords:** two case-sensitive counts before the release (the second is how many
  legacy hashes are left; nobody is affected by the release itself):
  `SELECT COUNT(*) FROM users WHERE password IS NOT NULL AND password NOT REGEXP BINARY

## Running agents (how)

- Workflow: implementer → orchestrator check → independent reviewer → fixes by the implementer →
  a second review only if the fixes are material → results recorded in the plan.
- One sbt/test JVM at a time across all agents: `mkdir /c/scala/.sbt-jvm.lock` before a run
  (wait and retry if it exists; never delete another's lock), `rmdir` after.
- Checks through `python scripts/agent-check.py -- …` from Git Bash (CLAUDE.md). Affected specs
  per batch; the full suite at the release boundary.
- Commit with `git commit -- <paths>`; the attribution line. No push and no PR, unless the user
  asks for one in that task; stack branches are pushed by the orchestrator (workflow practices
  §6.3).
- Never link or copy `node_modules` or `data/cache` between worktrees. `C:/scala/wlxjury` (main
  checkout, user's untracked files) and `C:/scala/wlxjury-infra` (user's uncommitted work, secrets)
  are not modified by agents.
