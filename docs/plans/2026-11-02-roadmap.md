## Running agents (how)

The rules are in [workflow practices](../workflow/practices.md); in short:

- Workflow: implementer → orchestrator check → independent reviewer → fixes by the implementer →
  a second review only if the fixes are material → results recorded in the plan (§2).
- **Only the orchestrator pushes and opens PRs** (an agent only when the user asks for it in
  that task), never with force; edits to another agent's PR body go through the orchestrator or
  the user (§6.3).
- **gh** is `/c/Users/ilya/tools/gh/bin/gh.exe` (not on `PATH`; the review tools take it from
  `GH` or `--gh`). Agents use it read-only unless told otherwise.
- **One sbt/test JVM at a time** across all agents: take `mkdir /c/scala/.sbt-jvm.lock` as its
  own command and check it succeeded (wait and retry if it exists; never delete another's lock),
  `rmdir` after, only if yours (§4.2).
- **Every sbt or Docker run** with the prefix
  `env -u COMMONS_USER -u COMMONS_PASSWORD -u SCALAWIKI_LOGIN -u SCALAWIKI_PASSWORD` (§4.3).
- Checks through `python scripts/agent-check.py -- …` from Git Bash (CLAUDE.md). Affected specs
  per batch; the full suite at the release boundary (CI runs it on every PR).
- Commit with `git commit -- <paths>` and `-F <file>`; the attribution line (§5).
- **Restack by merge, never by force:** a stack branch that needs a lower PR's change gets a
  merge commit (or a new commit), never a rebase or force push of a pushed branch (§6.5).
- **Followups mirrors equal the stack tip by tree:** a commit on the top stack PR is mirrored on
  a followups branch (`git commit-tree <tip>^{tree} -p <followups>`) and `git diff --stat` is
  empty (§6.4).
- Never link or copy `node_modules` or `data/cache` between worktrees. `C:/scala/wlxjury` (main
  checkout, user's untracked files) and `C:/scala/wlxjury-infra` (user's uncommitted work, secrets)
  are not modified by agents.
- CodeRabbit: [`scripts/review/`](../../scripts/review/README.md), one PR at a time.
